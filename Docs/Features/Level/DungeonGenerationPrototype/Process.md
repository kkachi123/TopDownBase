# 던전 생성 프로토타입 — 과정

상위 문서: [레벨 분야 과정](../Process.md) · [전체 개발 과정](../../../../PROCESS.md) · 구조와 사용법: [던전 생성기 가이드](../DungeonGenerator_Guide.md)

## 목표

보스 투기장 앞의 던전 구간을 손 배치 없이 생성할 수 있는지 확인한다. 실행하면 방 8개 안팎의 던전이 만들어지고, 임시 이동체로 걸어 다니며 방 크기·문·장애물·스폰 위치를 볼 수 있다.

[초기 게임 기획서](../../../TopDownBase_Initial_Game_Plan.md)의 진행 구조인 "생성된 던전 → 보스 투기장" 중 던전 부분을 담당한다. 현재는 프로토타입 단계다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `Assets/Game/Scripts/Dungeon/DungeonLayout.cs` | Growing Tree로 방 연결 그래프 생성, 역할 지정, 조건 미달 시 재생성 |
| `Assets/Game/Scripts/Dungeon/DungeonGenerator.cs` | 방 조립(바닥·벽·문), 장애물 스탬프, 적 스폰 위치, NavMesh 빌드 |
| `Assets/Game/Scripts/Dungeon/DungeonRoom.cs` | 방별 역할·스폰 위치·문 차단물 보관, 문 잠금 전환 |
| `Assets/Game/Scripts/Dungeon/DungeonPortal.cs` | 보스 입구 방의 포털. 열린 상태에서 플레이어가 들어오면 보스 씬을 불러옴 |
| `Assets/Game/Scripts/Dungeon/DungeonKeyPickup.cs` | 아이템 방의 열쇠. 닿으면 포털을 엶 |
| `Assets/Game/Scripts/Dungeon/Editor/DungeonGeneratorEditor.cs`, `.uss` | 인스펙터의 생성·지우기 버튼과 상태 안내 (UI Toolkit) |
| `Assets/Game/Scripts/Dungeon/Prototype/` | 확인용 임시 이동체와 카메라. 게임 플레이어가 아니며 TopDown Engine과 연결되지 않음 |
| `Assets/Game/Scripts/Dungeon/Editor/DungeonPrototypeSceneBuilder.cs` | 메뉴로 확인용 씬 생성 |

핵심 규칙:

- **방 배치:** 격자 중앙에서 시작해 방을 하나씩 잇는다. `NewestPickChance`가 1이면 Recursive Backtracking(일자형), 0이면 가지가 많은 방사형이다. 기본값 0.6.
- **역할:** 시작 방에서 가장 먼 방이 보스 입구, 나머지 막다른 방이 아이템 방, 그 외가 전투 방이다.
- **재생성 조건:** 보스 입구까지 5방 이상, 아이템 방 1개 이상. 50회 안에 못 찾으면 가장 가까운 배치를 쓰고 경고를 남긴다.
- **장애물:** 스탬프 5종을 벽에서 2칸, 서로 5칸 이상 띄워 놓는다. 이 규칙으로 빈 칸이 모두 이어지므로 도달 가능성 검사를 하지 않는다.
- **보스 포털:** 보스 입구 방의 포털이 `BossSceneName` 씬을 불러온다. 투기장 규격에 의존하지 않도록 씬 이동으로 연결했다(2026-11-17 개발자 결정). 보스 씬은 Build Settings에 등록되어 있어야 하며 현재 `SampleScene`을 쓴다.
- **열쇠:** 아이템 방 중 한 곳에 놓이고, 얻기 전에는 포털이 잠겨 있다. 아이템 방이 없는 배치에서는 포털을 열어 둔다. 포털과 열쇠는 `Player` 태그에 반응한다.
- **주변 환경:** 던전 아래 바닥과, 방 밖 빈 칸의 환경 프리팹 자동 배치. 방 남쪽에 붙은 빈 칸은 카메라 가림을 막기 위해 방 쪽을 비운다. NavMesh 빌드에서 제외한다.
- **형상:** 방은 전부 기본 도형이다. KayKit 모듈은 연결하지 않았다.
- **색:** 색상별 머티리얼을 하나씩 만들어 함께 쓴다. 씬에 같이 저장되므로 에디터에서 만든 맵을 저장해도 색이 유지된다.
- **빌드 제약:** 바탕이 되는 렌더 파이프라인 기본 머티리얼은 에디터에서만 제공되므로 빌드에서는 `BaseMaterial`을 지정해야 한다.
- **에디터 생성:** 편집 모드에서도 생성할 수 있다. NavMesh는 편집 모드에서 검사만 하고 남기지 않으며 Play 시작 시 다시 빌드한다.
- **Play 동작:** `GenerateOnAwake`가 켜져 있으면 다시 생성하고, 꺼져 있으면 씬에 저장된 맵을 그대로 쓴다.
- **참조 방식:** `Find` 계열 탐색 함수를 쓰지 않는다. 생성 결과는 직렬화된 참조로 보관하고, 외부에서는 인스펙터 할당이나 의존성 주입으로 생성기를 받는다.

기본 설정(5×5 격자, 방 8개, 0.6)에서 3,000회 측정: 보스 입구까지 평균 5.9방, 아이템 방 평균 1.5개, 배치 시도 평균 1.35회, 조건 미달 0건.

AI 검증은 2026-11-16에 Unity 6000.6.0f1 에디터에서 수행했다. 빌드에서는 실행하지 않았다.

## 개발자 확인 방법

1. `Assets/Scenes/DungeonPrototype.unity`를 연다. 메뉴 **TopDownBase > Dungeon Prototype > Create Or Open Scene**으로도 열 수 있다.
2. Play를 누른다. 콘솔에 `[Dungeon] seed ...` 로그가 한 줄 나온다.
3. 조작: **WASD** 이동, **Tab** 누르는 동안 전체 보기, **R** 새 시드로 재생성, **L** 현재 방 문 잠금 전환. Game 창을 한 번 클릭해 포커스를 줘야 키가 들어간다.

확인할 항목:

- 하늘색 열쇠를 얻으면 포털 색이 바뀌고, 포털에 들어가면 보스 씬으로 넘어가는지. 열쇠 없이는 넘어가지 않는지.
- 주변 환경 프리팹의 밀도·크기와, 방 남쪽의 나무가 방 바닥을 가리지 않는지.
- 편집 모드에서 `DungeonGenerator`를 선택하고 인스펙터의 **현재 시드로 생성 / 무작위 시드로 생성 / 지우기** 버튼이 동작하는지.
- 버튼 아래 안내 상자가 생성 결과와 Play 시 동작을 맞게 보여 주는지.
- 방 크기(기본 24×20 유닛)가 전투에 충분한지. 콜로세움은 지름 32 유닛이다.
- 카메라 각도 40도에서 남쪽 벽(높이 2)이 바닥을 얼마나 가리는지.
- R을 여러 번 눌렀을 때 배치가 충분히 달라 보이는지.

## 다음 단계

- 개발자가 인스펙터의 생성·지우기 버튼을 직접 눌러 확인한다.
- 방 크기·벽 높이·`NewestPickChance`를 확인 결과에 맞춰 조정한다.
- KayKit 모듈로 방 형상 교체, 방 잠금과 적 스폰 연동.
- 보스 씬 확정(투기장 규격, 보스 구성), 씬 사이 플레이어 상태 전달, 이동 연출.
- 외부 환경 에셋을 더해 주변 환경 완성.
- 방 수와 크기를 기획서의 플레이 목표 시간에 맞춰 조정한다.
