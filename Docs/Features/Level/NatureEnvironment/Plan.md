# 자연환경 맵 계획

상위 문서: [레벨 분야 과정](../Process.md) · 진행 기록: [과정](Process.md) · 근거 자료: [맵 경계 표현 테스트](../LayoutTests.md)

## 목표

던전 구간을 "불규칙 공터 + 굽은 길 + 자연물 경계"로 생성한다. 한 판 흐름(탐색 → 열쇠 → 포털 → 보스 씬)이 이 환경에서 동작하고, 환경 세팅 에셋만 바꿔 다른 분위기의 맵을 만들 수 있다.

## 변경 범위

출발점은 `Assets/Game/Scripts/Dungeon/Experiments/`의 테스트 코드였다. 3단계에서 본 생성기로 옮기고 실험 코드와 테스트 씬은 지웠다.

- `Assets/Game/Scripts/Dungeon/WalkableMap.cs`: 걸을 수 있는 영역 지도. 길 입구 위치(2단계)와 적 스폰 위치(3단계)를 계산한다.
- `Assets/Game/Scripts/Dungeon/DungeonGenerator.cs` (+ `.Ground.cs`, `.Props.cs`): 자연환경 생성기. 지면은 Terrain, 소품은 묶어 그리기. 적 스폰, 열쇠, 포털, 방 잠금을 새 구조로 옮겼다(3단계).
- 신규 환경 세팅 에셋(ScriptableObject): 지면·길 텍스처, 가장자리 소품, 바깥 소품, 장애물, 문 오브젝트, 후처리, 밀도와 크기(4단계).
- `Assets/Scenes/DungeonPrototype.unity`: 3단계부터의 확인용 씬. 1~2단계는 `Assets/Scenes/Experiments/NatureLayoutTest.unity`(삭제됨)에서 확인했다.

필요한 제약·결정:

- **걸을 수 있는 영역은 높이 0의 평지다.** 높낮이는 경계 바깥에만 주고, 캐릭터 키(2유닛)보다 낮게 둔다. 경계가 높으면 남쪽 가장자리의 캐릭터가 가려진다.
- **Terrain은 지면 층으로만 쓴다.** 텍스처 칠하기로 공터 가장자리를 부드럽게 한다. 이동을 막는 것은 보이지 않는 충돌체다.
- **소품은 GameObject 없이 `Graphics.RenderMeshInstanced`로 그린다.** 화면에 보이는 소품만 골라 프리팹 종류마다 한 번에 그린다. 프리팹은 루트에 메시 하나가 있는 형태여야 한다. Terrain의 나무 기능과 런타임 메시 합치기는 쓰지 않는다(전자는 묶이지 않았고, 후자는 소품 메시의 Read/Write가 꺼져 있어 외부 에셋의 임포트 설정을 바꿔야 한다).
- **방 남쪽에는 키 큰 소품을 놓지 않는다.** 소품의 높이와 카메라 각도로 가리는 거리를 계산해 판단한다.
- **장애물과 경계 사이는 4유닛 이상.** NavMesh 에이전트 반지름이 1유닛이다.
- **참조는 인스펙터 할당과 주입으로 전달한다.** `Find` 계열을 쓰지 않는다.
- **생성물은 씬에 저장하지 않는다.** Terrain 데이터가 메모리에만 있기 때문이다.

개발자 결정 (2026-11-18, 3단계 전):

- 벽 방식 던전을 이 환경으로 **대체**한다. 벽 방식 코드는 Git 기록에만 남긴다.
- 기획서는 3단계 완료 뒤에 반영한다.
- 에디터에서 만든 맵을 저장해 손으로 고치는 기능은 이번에 넣지 않는다. 필요해지면 Terrain 데이터를 에셋으로 저장하는 처리가 추가된다.
- 실험 코드와 테스트 씬 두 개는 본 생성기로 흡수한 뒤 지운다.

## 핵심 단계

- [x] **1. 기술 검증:** Terrain 지면(평지 + 바깥 낮은 언덕 + 텍스처 칠하기)과 묶어 그리는 소품. 결과: 1단계 기준 통과(AI 검증), 개발자 확인 완료(2026-11-18).
- [x] **2. 경계와 문:** 가장자리를 촘촘히 채우거나 낮은 턱을 둬 경계가 화면에서 읽히게 한다. 길이 공터와 만나는 지점을 계산하고 그 자리에 잠금 오브젝트를 둔다. 결과: 2단계 기준 통과(AI 검증), 개발자 확인 완료(2026-11-18).
- [ ] **3. 본 생성기로 통합:** 적 스폰 위치, 열쇠, 보스 포털을 새 구조로 옮긴다. 결과: `DungeonPrototype`의 한 판 흐름이 자연환경에서 동작한다. 현재: 3단계 기준 통과(AI 검증, 2026-11-18), 개발자 확인 필요.
- [ ] **4. 환경 세팅 데이터화:** 세팅 에셋을 만들고 생성기가 이를 받아 쓴다. 결과: 세팅 에셋만 바꿔 다른 환경이 생성된다. 두 번째 세팅을 하나 만들어 확인한다.
- [ ] **5. 전투 공간 조정:** 공터 크기, 길 폭, 장애물 수와 크기. 플레이어와 적이 구현된 뒤에 진행한다.
- [ ] **6. 빌드 확인:** 빌드용 머티리얼 지정, Terrain 셰이더 포함, 생성 시간.

## 검증 기준

현재 값(자연환경 테스트 씬, 방 12개, 2026-11-17 측정):

| 항목 | 현재 |
| --- | --- |
| DrawCall (따라가는 화면) | 984 (소품 제외 시 22) |
| 생성되는 GameObject | 1,663 |
| 가려지는 바닥 (공터 모양) | 13.7% |
| 생성 시간 (NavMesh 포함) | 40~48ms |

단계별 기준:

- **1단계:** 따라가는 화면 DrawCall 150 이하, 생성되는 GameObject 300 이하, 가려지는 바닥 14% 이하. 시드 40개에서 모든 방까지 NavMesh 경로 완성. 공터 가장자리가 계단 모양으로 보이지 않는다(화면 캡처로 확인).
- **2단계:** 시드 40개에서 모든 길 입구에 잠금 오브젝트가 하나씩 있고, 잠근 상태에서 이동체가 공터를 벗어나지 못한다. 연 상태에서는 NavMesh 경로가 유지된다.
- **3단계:** 스폰 위치가 모두 NavMesh 위에 있고, 열쇠 획득 → 포털 → 보스 씬 이동이 Play에서 동작한다.
- **4단계:** 세팅 에셋 두 개로 각각 생성했을 때 방 배치는 같고 소품과 지면만 달라진다.
- **5단계:** 개발자가 직접 플레이해 판단한다.
- **6단계:** Windows 빌드에서 생성, 이동, 포털 이동이 동작한다.

공통: 컴파일 오류 0, Play 진입·종료 후 생성물이 남지 않는다. AI 검증과 개발자 직접 확인을 구분해 기록하고, 확인하지 못한 항목은 완료로 표시하지 않는다.
