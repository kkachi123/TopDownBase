# TopDownBase — 초기 게임 기획서

> **문서 목적:** 새로운 개발 방식으로 다시 출발할 때 참고하는 게임의 **초기 방향과 최소 목표**. 구현 방식, 엔진 지원 여부, 최종 밸런스는 이 문서에서 확정하지 않는다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 장르 | Unity 3D 탑다운 근접 액션 로그라이트 |
| 개발 환경 | Unity `6000.6.0f1`, TopDown Engine 활용 |
| 참고작 | Hades의 빠른 회피·반격·타격감에서 영감 (복제 목적 아님) |
| 개발 방식 | 1인 개발, Windows PC 키보드·마우스 우선 |
| 목표 기간 | 1~2개월, 주 40시간 이상 투입 가능 |
| 개발 목적 | 게임 클라이언트 개발자 취업 포트폴리오 |
| 플레이 목표 | 약 5~8분의 짧고 완결된 데모 |

## 2. 핵심 재미

**적의 명확한 공격 패턴을 읽고 → 대시로 회피한 뒤 → 근접 공격으로 강하게 반격하는 경험.**

- 빠른 이동과 대시를 활용한 능동적인 회피
- 손맛이 느껴지는 근접 3타 콤보
- 예고된 공격 패턴을 관찰하고 빈틈을 공략하는 전투
- 정확한 회피가 공격 기회로 이어지는 보상

## 3. 최소 게임 구성

| 구분 | 필수 목표 | 비고 |
| --- | --- | --- |
| 플레이어 | WASD 이동, 마우스 방향 조준 | 최초에는 PC 입력만 지원 |
| 기본 공격 | 한손검 3타 콤보 | 동작감·타격 피드백 우선 |
| 대시 | 방향 이동 및 짧은 무적 | 기본 공격의 일부 구간 취소 허용 방향 |
| 특수 공격 | 강한 전방 찌르기 | 대시 취소 불가 방향 |
| 정확한 회피 | 적 공격 접촉 순간의 대시 회피 성공 판정 | 기술 가능성 검증 필요 |
| 회피 보상 | 다음 기본 공격 1회 강화, 중첩 없음 | 지속시간·배율은 테스트로 조정 |
| 적 | 근접형 1종, 원거리형 1종 | 각 1개 대표 패턴 우선 |
| 공격 가시성 | 바닥 공격 예고와 명확한 후딜레이 | 실제 판정과 예고 일치 |
| 진행 | 생성된 던전의 방을 지나 보스 투기장에 도달 | 던전은 플레이마다 새로 생성. 보스 입구 방의 포털로 보스 씬에 이동하며 던전으로 돌아오지 않는다 |
| 던전 | 전투 방과 아이템 방 | 아이템 방 중 한 곳의 열쇠를 얻어야 보스 포털이 열린다. 모든 방은 시작 방에서 도달 가능. 방 수·크기는 플레이 목표 시간에 맞춰 조정 |
| 보스 | 별도 씬의 투기장에서 전투 | 투기장 규격, 보스 구성과 패턴은 미확정 |
| 강화 | 방 완료 후 간단한 선택 | 기본 공격/대시/특수 공격 강화 중심 |
| 종료 흐름 | 사망·재시작·클리어 | 한 판 완결 가능 |

**초기 밸런스 실험 예시(확정값 아님):** 정확한 회피 후 강화 유지 약 3초, 다음 기본 공격 약 1.5배 피해. 실제 플레이 테스트로 변경 가능.

## 4. 아트와 조작감

- 최종 방향은 스타일라이즈드 로우폴리 3D.
- 초기 개발은 임시 모델과 단순한 전투 공간을 허용한다.
- 공격 애니메이션, 피격 반응, 타격음, 히트스톱, 이펙트는 **가독성과 조작감**을 기준으로 조정한다.
- 보유 또는 외부 에셋을 활용하되 원본 에셋 내부 코드와 원본 데모 파일은 직접 수정하지 않는다.

## 5. 구현 범위 원칙

**필수:** 전투 조작, 정확한 회피/보상, 적 2종, 생성되는 던전과 보스 투기장, 최소 UI, 재시작, 플레이 가능한 빌드.

**후순위:** 충격파처럼 전투를 변화시키는 추가 강화, 게임패드·모바일 UI, Addressables 학습, 추가 패턴.

**MVP 제외:** 여러 무기·클래스, 복잡한 인벤토리·상점, 영구 성장, 서버 로그인/뒤끝 연동, 과도한 범용 프레임워크.

PlayMaker 등 추가 도구는 실제 필요성과 기존 엔진의 기능을 확인한 뒤에만 도입한다.

## 6. 완료 판단

1. 짧은 플레이 안에 이동·회피·반격의 핵심 재미가 전달된다.
2. 전투 패턴과 피해 판정이 읽기 쉽고 공정하게 느껴진다.
3. 시작부터 던전과 보스 투기장을 거쳐 사망 또는 클리어까지 정상적으로 플레이된다. 던전은 어떤 시드로 생성해도 시작 방에서 열쇠와 보스 포털까지 이동할 수 있다.
4. 게임을 막는 주요 버그가 없고, 실제 플레이 테스트를 거쳤다.
5. 직접 작성한 코드와 TopDown Engine 재사용 부분을 구분하여 설명할 수 있다.

## 7. 설계상 남겨둘 결정

게임의 기본 방향은 위와 같지만, **세부 전투 타이밍·카메라·입력 바인딩·적의 패턴 난이도·강화 수치·던전의 방 수와 크기·아이템 방의 보상·보스 투기장 규격·보스 구성과 패턴·실제 구현 순서**는 사용자가 코드와 플레이 경험을 이해하고 검증하면서 점진적으로 결정한다.
