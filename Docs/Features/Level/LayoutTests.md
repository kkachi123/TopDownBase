# 맵 경계 표현 테스트

상위 문서: [레벨 분야 과정](Process.md)

게임 기획에 포함된 기능이 아니다. 던전의 방 경계를 벽 대신 다른 방식으로 표현했을 때 어떻게 되는지 별도 씬에서 배치해 본 기록이다. 현재 던전 생성기와 `DungeonPrototype` 씬의 동작은 바꾸지 않았다.

## 무엇을 비교했나

| 씬 | 경계 표현 | 기본 방 모양 |
| --- | --- | --- |
| `Assets/Scenes/Experiments/TerrainBoundaryTest.unity` | Unity Terrain의 높낮이 | 직사각형 |
| `Assets/Scenes/Experiments/NatureLayoutTest.unity` | 바위·덤불·나무 소품 + 보이지 않는 충돌체 | 불규칙 공터 + 굽은 길 |

두 씬 모두 빌더의 `Shape`를 `Rectangle`과 `Clearing` 사이에서 바꿀 수 있다. 방 그래프는 던전 생성기와 같은 `DungeonLayout`을 쓴다.

## 실행 방법

1. 메뉴 **TopDownBase > Layout Tests**에서 씬을 연다.
2. Play를 누르거나, 빌더 오브젝트를 선택해 인스펙터의 **현재 시드로 생성 / 무작위 시드로 생성 / 지우기** 버튼을 쓴다.
3. 조작: **WASD** 이동, **Tab** 전체 보기, **R** 새 시드로 다시 생성. Game 창을 한 번 클릭해야 키가 들어간다.

생성물은 씬에 저장되지 않는다. 편집 모드에서 만든 맵은 Play를 누르거나 스크립트가 다시 컴파일되면 사라진다.

## 구성

모두 `Assets/Game/Scripts/Dungeon/Experiments/` 아래에 있다.

| 파일 | 역할 |
| --- | --- |
| `WalkableMap.cs` | 방 그래프에서 "걸을 수 있는 영역" 지도를 1유닛 해상도로 만든다. 방 모양, 길, 경계까지의 거리, 장애물 위치 |
| `LayoutTestBuilder.cs` | 두 테스트의 공통 기반. 생성 흐름, 장애물과 표식, NavMesh 빌드와 검사, 가려지는 바닥 비율 측정 |
| `TerrainBoundaryBuilder.cs` | 지도에서 높이맵을 만들어 Terrain으로 경계를 세운다 |
| `NatureBoundaryBuilder.cs` | 소품으로 경계를 표현하고, 걸을 수 없는 칸을 보이지 않는 상자로 막는다. 이 테스트 이후 지면과 소품 그리는 방식이 바뀌었다([자연환경 맵 과정](NatureEnvironment/Process.md)) |
| `Editor/LayoutTestBuilderEditor.cs` | 인스펙터의 생성 버튼 |
| `Editor/LayoutTestSceneBuilder.cs` | 테스트 씬을 만들거나 여는 메뉴 |

기존 코드는 한 가지만 바꿨다. 임시 이동체와 카메라가 테스트 씬에서도 쓰이도록 `DungeonMapSource`(시작 위치, 재생성, 전체 영역)를 두고 `DungeonGenerator`가 이를 상속하게 했다. 동작은 같다.

## 측정 결과 (2026-11-17, Unity 6000.6.0f1 에디터)

구성마다 시드 20개(방 8개와 12개를 번갈아)를 생성해 평균을 냈다.

| 구성 | 가려지는 바닥 | 방 넓이 | 방 사이 길 | 방 간격 | 생성 시간 | 오브젝트 |
| --- | --- | --- | --- | --- | --- | --- |
| 현재 던전 (벽) | 11.7% | 480 | 1 (벽 두께) | 25×21 | 5ms (NavMesh 제외) | 146 |
| Terrain, 직사각형 | 12.2% | 480 | 6.0 | 30×26 | 119ms | 38 |
| Terrain, 공터 | 17.3% | 310 | 8.7 | 30×26 | 68ms | 29 |
| 소품, 직사각형 | 11.9% | 525 | 4.7 | 29×25 | 43ms | 1,472 |
| 소품, 공터 | 13.7% | 312 | 7.5 | 29×25 | 40ms | 1,427 |

- **가려지는 바닥:** 카메라 각도 40도 방향으로 광선을 쏴, 걸을 수 있는 면적 중 경계나 장애물에 가려지는 비율.
- **방 넓이·방 사이 길·방 간격:** 유닛 기준. 방 넓이는 방 하나의 걸을 수 있는 면적, 방 사이 길은 연결 하나의 평균 길이다.
- **생성 시간:** 테스트 씬은 NavMesh 빌드를 포함한다. 현재 던전은 NavMesh를 포함하면 8ms였다(이전 측정).

검증: 두 씬 80개 맵 모두 시작 방에서 모든 방까지 NavMesh 경로가 이어졌고, 경계 안쪽으로는 경로가 생기지 않았다. Play 모드에서 이동체가 경계에서 멈췄고, Play 종료 후 생성물이 남거나 씬이 변경된 것으로 표시되지 않았다. `WalkableMap`은 에디터 밖에서 6,000개 맵으로 연결성과 장애물 규칙을 따로 확인했다.

## 알게 된 것

### Terrain 경계

- **구조는 그대로 유지된다.** 방 그래프와 장애물 규칙을 건드리지 않고 경계만 높낮이로 바꿀 수 있었다. NavMesh도 Terrain에서 정상적으로 만들어졌다.
- **평균 가림은 벽과 비슷했다(12.2% 대 11.7%).** 높이 4유닛인데도 경사가 완만하게 올라가 방 안쪽을 덜 가린다. "벽보다 두 배 가린다"는 처음 추정은 수직 벽을 가정한 것이라 틀렸다.
- **남쪽 가장자리에 선 캐릭터는 거의 가려진다.** 경계 높이(4)가 캐릭터 키(2)보다 높아서다. 평균 수치에는 드러나지 않는 문제다.
- **공간을 더 쓴다.** 경사를 넣을 폭이 필요해 방 간격이 25×21에서 30×26이 됐다(면적 49% 증가). 방 사이 이동도 1유닛에서 6유닛으로 늘었다.
- **모양이 매끈하다.** 각진 로우폴리 에셋과 질감이 다르다.
- **생성 시간이 가장 길다(119ms).** 한 번 생성하는 용도로는 문제없는 수준이다.

### 소품 경계와 공터

- **불규칙 공터와 굽은 길이 자연환경 느낌을 만든다.** 직사각형 방에 소품만 두른 것과 인상이 크게 다르다.
- **공터는 전투 공간이 줄어든다.** 같은 방 크기에서 넓이가 480에서 312로 줄었다(65%). 전투 공간을 유지하려면 `RoomSize`를 키워야 하고, 그만큼 맵이 커진다.
- **방 사이 길이 7.5유닛이다.** 전투 없는 이동 구간이 생긴다.
- **소품 크기가 가림을 좌우한다.** 가장자리 소품 배율이 1.2~2.0일 때 가림이 27~35%였고, 0.7~1.2로 줄이자 12~14%가 됐다. 큰 소품이 걸을 수 있는 영역 위로 넘어오기 때문이다.
- **오브젝트가 1,400개 안팎으로 늘어난다.** 대부분 소품 복제본이다.
- **공터 가장자리가 계단 모양으로 보인다.** 지도가 1유닛 칸이라 생기는 모양이며 다듬지 않았다.

### 공통

- **장애물 여유는 NavMesh 에이전트 반지름에 맞춰야 한다.** 이 프로젝트의 에이전트 반지름은 1유닛이다. 장애물과 경계 사이를 3유닛으로 뒀을 때 맵의 절반가량에서 통로가 막혔고, 4유닛으로 늘리자 0건이 됐다.
- **충돌체가 달린 소품 프리팹은 길을 막는다.** POLY STYLE의 Grass가 그랬다. 소품은 복제할 때 충돌체를 떼고 NavMesh 빌드에서 제외했다.

## 한계

- 소품의 가림은 소품을 원기둥으로 근사해 계산했다. 나무처럼 위쪽만 넓은 모양은 실제보다 많이 가리는 것으로 나온다.
- 화면 품질, 조작감, 전투는 평가하지 않았다. 적과 플레이어 전투가 없는 상태다.
- R 키는 키 입력 시뮬레이션으로 확인되지 않아 개발자 확인이 필요하다.
- 빌드에서는 실행하지 않았다.
